# [높음] 2026-09-09 스마트 스킵 상시 실패 → 매번 캡차 요구

- **발생 일시**: 2026-09-09
- **심각도**: 높음 (자동조회 목적 훼손)
- **관련 파일**: `src/interactive_runner.js`, `src/PageController.js`

---

## 1. 증상

이미 GUI/이전에 한 번 조회·저장한 사건인데도 로그에 거의 매건:

```
[Smart Skip] 최근 검색 내역 확인 중: ...
i [Smart Skip] 최근 검색 내역 없음 -> 정보 입력 진행
```

자동입력방지문자(캡차)를 계속 요구했다.

사용자는 “최초 조회 한 번 하면 다음은 자동조회 가능해야 한다”고 했다.

## 2. 영향 범위

- CLI/GUI 자동 경로에서 캡차 생략이 거의 동작하지 않음
- 수동 입력·OCR·실패 재시도 부담 증가

## 3. 근본 원인 (복합)

### (1) 타이밍

`navigateToSite()`는 `body`만 보고 “접속 완료”로 친다.
대법원 WebSquare는 최근 검색을 **이후 AJAX**로 붙이는데,
예전 스캔은 접속 직후 `a`/`td`를 **한 번만** 정확 일치로 봤다 → 빈 목록.

### (2) 매칭이 너무 빡셈

`textContent.trim() === 사건번호`만 허용.
공백·하이픈·`span` 안의 번호는 놓쳤다.

### (3) `about:blank`로 페이지 비움

같은 레인 다음 사건 전에 `about:blank` 후 재접속 → 최근 검색 UI(페이지 메모리)가 비었다.

### (4) 프로필은 이미 고정

사건번호 → `instance_N` 해시는 있었다.
문제는 “같은 창에 기록이 있는데도 못 찾는 것”이었다.
(프로필 수 변경·다른 instance에서만 조회한 건은 여전히 캡차 필요 — 사이트 한계)

### (5) WORKER_IDLE 가짜 실패와 겹침

레인이 자주 죽으면 Chrome이 새로 떠서 스킵이 더 자주 리셋됐다.
→ `ERROR_20260909_worker_idle_false_fail.md` 참고.

## 4. 왜 막지 못했나

- “접속 완료 = 검색 UI 준비”로 착각
- 스마트 스킵 실패를 “기록 없음”으로만 로그해 원인 구분이 어려웠음
- `about:blank`가 최근 검색에 미치는 영향이 문서화되지 않음

## 5. 복구 방법

코드 수정 후 재실행. 2026-09-09 CLI 재실행에서는 대부분 `최근 검색 내역 발견` / `CLICK` 으로 통과.

## 6. 재발 방지 코드 — 지우지 말 것

| 위치 | 가드 |
| --- | --- |
| `PageController.waitForSearchForm` | 사건번호 입력칸이 뜰 때까지 대기 |
| `PageController.scanRecentCase` | 수 초간 폴링 + 공백/하이픈 정규화 + a/td/span/li |
| `PageController.clickRecentCase` | 동일 정규화로 클릭 |
| `interactive_runner` 워커 루프 | 같은 레인에서 `about:blank` 하지 않음 |

## 7. 교훈

1. **SPA/WebSquare는 body 직후 DOM을 믿지 말 것.** 검색 폼·목록을 따로 기다려라.
2. **세션 UI를 blank로 끊으면 “저장했는데 없는” 현상이 난다.**
3. **스킵 실패 로그에 목록 샘플을 남겨** “타이밍/미저장/다른 프로필”을 구분할 것.
